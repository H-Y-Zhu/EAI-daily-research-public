Programmable World Model

Zheng-Hui Huang, Guixu Lin, Jiacheng Lin, Yi-Chuan Huang, Ruihan Yu, Muyao Niu
abspdf

论文点评Review

这篇 Programmable World Model 试图用“显式状态 + 生成渲染”的解耦方案解决视频世界模型“记性差”的问题。虽然把状态和画面分开确实能让角色不死不活地存在，但把游戏逻辑写成代码显然限制了开放世界的自由度，更像是在做可编程的动画引擎而非真正的世界模型。CombatStateBench 虽然测得准，但仅限于战斗场景，能不能跑赛车还得看。基线对比里，LingBot 和 YUME 在状态一致性上确实被按在地上摩擦，但 PWM 依赖的 3D OBB 在复杂遮挡下会不会崩，还是个问号。总的来说，这是一次在可控性和生成能力之间的务实妥协，适合特定场景但离通用智能还有距离。

研究动机Motivation

现有视频世界模型 [2, 16, 17, 18] 虽然画面逼真，但缺乏持久状态，实体容易“薛定谔地消失”，难以维持长程交互的一致性。StatePlay [14] 和 MASS [3] 尝试引入显式状态，但前者状态由模型预测易累积误差，后者依赖学习到的逻辑引擎，不如直接可编程来得可控。现有方法难以直接操作单个实体或定义规则，比如“门开了”这种逻辑很难通过 Prompt 稳定实现，且缺乏对屏幕外实体的记忆。这导致在长 horizon 生成中，角色数量、状态和交互结果经常发生漂移，无法满足游戏或仿真对确定性的需求。
—

方法Method

整体流程分为四步：1. Coding Agent 将自然语言转为可执行程序；2. 轻量引擎维护显式世界状态（3D OBB+ 属性）；3. Control Compiler 将 OBB 投影为 Identity/Semantic/Direction 三张控制图；4. 生成渲染器基于这些图和相机轨迹生成视频。创新点在于用 3D OBB 作为中间表示，既保留了空间一致性，又避免了完整 3D 重建的高成本。Identity Map 解决跨帧实体对应，Direction Map 区分相机运动与物体运动。渲染器基于 LingBot-World-v1，通过 ControlNet 注入控制信号，并采用 Chunk-Autoregressive 机制支持长序列生成。数据方面，利用 ViPE 和 SAM3 自动从游戏视频提取标注，解决了训练数据稀缺问题，实现了从视频到结构化控制信号的自动化流水线。
—

实验Experiments

在 CombatStateBench 上测试，包含 50 个战斗场景 clip。基线对比 LingBot-World-V2 [5] 和 YUME [15]。指标包括 Count Accuracy 和 State Accuracy，由 VLM 裁判评估。PWM 达到 94% 和 98%，远超基线（LingBot 仅 40% 和 8%）。定性结果展示了在动态相机和实体移动下，角色死亡状态和场景一致性保持得更好。消融实验未详述，但数据流水线的有效性隐含在训练设置中。结果表明显式状态管理能显著提升视频生成的逻辑一致性，特别是在涉及实体消亡和数量统计的任务中。
