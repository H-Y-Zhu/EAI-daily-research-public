KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

Zirui Liu, Jiayi Yuan, Hongye Jin, Shaochen Zhong, Zhaozhuo Xu, Vladimir Braverman
abspdf

论文点评Review

KIVI 这论文算是给 LLM 推理的“内存焦虑”开了个猛药。2bit 量化？听着就像让精密仪器去工地搬砖，但作者硬是让它跑起来了。亮点在于不对称量化，Key 按通道，Value 按 Token，这直觉挺准，直接戳中了 KV Cache 分布的痛点。不过，Falcon 模型在 2bit 下直接崩了，得回退到 4bit，这“一刀切”的自信有点危险，说明模型架构差异不能忽视。虽然吞吐量提升了 3 倍多，但残差部分全精度保留，这算不算“既要又要”？毕竟 2bit 的压缩比是实打实的，只是对某些模型来说，精度损失还是得靠残差窗口硬扛。总的来说，是个实用的工程 trick，省显存是真省，但别指望它拯救所有架构，尤其是那些对精度极度敏感的长文本任务，毕竟残差部分占用的显存虽然少，但也不能完全忽略。

研究动机Motivation

LLM 推理的 KV Cache 早就成了显存杀手，Pope et al. (2023) 指出 540B 模型在特定场景下 KV Cache 能占 3TB，比参数还大，直接卡死推理速度。现有方案要么改架构（MQA/MGA，Shazeer, 2019），要么剪枝（H2O, Zhang et al., 2023），要么系统级卸载（vLLM, Kwon et al., 2023）。量化虽简单，但 KV Cache 流式特性让传统 GPTQ 难以下手，且现有量化多针对权重。Sheng et al. (2023) 的 FlexGen 用了 4bit，但 2bit 研究匮乏，且缺乏对元素分布的深入理解。更关键的是，没人深究 KV Cache 的元素分布，导致盲目量化容易崩。作者发现 Key 有 outlier 通道，Value 没有，这直接决定了量化策略不能“一视同仁”，否则精度会像过山车一样。这不仅是压缩问题，更是对注意力机制内部数据的重新认识。
—

方法Method

KIVI 核心是“不对称 + 流式”。Pipeline 分 Prefill 和 Decoding。Prefill 生成 KV，Decoding 更新 KV。创新点在于 Key 和 Value 采用不同量化粒度。Key 缓存存在固定通道 magnitude 极大，所以按 Channel 量化，把误差锁死在通道内，不影响其他正常通道。Value 缓存用于注意力输出加权求和，且注意力稀疏，按 Token 量化能隔离误差，避免一个 Token 的误差污染全局。为了解决流式更新问题，作者设计了“分组 + 残差”结构：大部分 Token 分组量化（Grouped），最近 R 个 Token 全精度保留（Residual）。解码时，Attention 计算分两部分拼接，利用 Tiled Matrix Multiplication。这保证了新 Token 能直接追加，同时残差窗口维持了局部精度。系统层融合反量化与矩阵乘法，减少 CUDA 开销，实现硬件友好。这种设计巧妙地平衡了压缩率和精度，避免了传统流式量化无法处理 Channel 维度的问题。
—

实验Experiments

在 Llama-2, Falcon, Mistral 上测试，任务涵盖 CoQA, TruthfulQA, GSM8K, LongBench。基线是 16bit 和 4bit 量化。结果上，Llama/Mistral 的 2bit KIVI 精度几乎无损（GSM8K 仅降 2%），但 Falcon 7B 在 2bit 下精度暴跌，需 4bit 维持，说明 Multi-Query Attention 对量化更敏感。NIAH 长上下文检索任务中，2bit 仍保持能力，证明没丢失关键信息。效率方面，显存峰值降 2.6 倍，Batch Size 扩 4 倍，吞吐量提升 2.35-3.47 倍。消融实验显示残差长度 R 对硬任务（如数学推理）至关重要，Group Size 过大则效果下降。这证明了全精度窗口在关键区域的重要性。实验数据充分，但 Falcon 的失败也提醒我们，通用方案总有边界。
