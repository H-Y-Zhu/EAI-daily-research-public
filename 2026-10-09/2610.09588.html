Adaptive Code Generation for Controlling Robots

Justus Flerlage, Thorsten Wittkopp, Alexander Acker, Odej Kao
abspdf

论文点评Review

这篇论文给 LLM 机器人穿了件“防弹衣”。作者认为直接让 LLM 输出动作太飘，不如让它写 Python 代码，至少能语法检查。架构基于经典的 MAPE-K 闭环，把感知、规划、执行串起来。亮点是状态快照和热重载，允许机器人边跑边改代码，避免重置任务。缺点嘛，LLM 还是可能幻觉，无限任务下容易迷路或过早停止，对长程推理要求高。总的来说，是给 LLM 加了个沙盒，但子弹还是 LLM 自己造的，可靠性依赖模型本身，开源模型似乎比闭源更稳。虽然解决了形式化问题，但语义理解依然是黑盒，且对模型推理速度要求极高。

研究动机Motivation

传统机器人依赖静态假设 [11, 16]，遇到未知物体就傻眼，无法泛化到开放环境。LLM 虽能理解自然语言 [6, 17, 18]，但缺乏物理落地能力，输出非确定性。本文要解决三个 gap：形式化（意图变代码）、分类学（未知物体）、时间状态（进度丢失）。需要一种既能灵活理解意图，又能保证执行安全的架构。引用 [4] 说明 MAPE-K 的适用性。现有工作如 VLA [27] 直接映射动作，缺乏中间代码层，难以调试和验证。因此，需要一种结合生成式 AI 灵活性与传统控制可靠性的混合架构，以应对动态环境中的不确定性。
—

方法Method

整体是 MAPE-K 闭环。感知层用 LiDAR 聚类生成 AABB，VLM 补充语义，融合成世界状态。认知层 LLM 生成受限 Python 代码，约束在预定义库内。执行层用虚拟机快照支持热重载，保留指令指针和变量绑定。触发器包括新物体、几何变化、语义发现，触发重规划。核心创新在于将 LLM 输出限制为可验证代码，并通过 VM 实现状态保持，确保动态环境下的连续性。LiDAR 使用动态距离阈值聚类，VLM 异步推理，确保实时性。虚拟机支持代码热重载，无需重启进程即可更新逻辑，这对长时任务至关重要。
—

实验Experiments

Gazebo 仿真，四足机器人。任务分有限（Go to X）和无限（Explore until X）。对比 Qwen3.5, GPT-5-nano, Kimi-K2.5。指标 SR, SE, RF。开源模型表现更好，GPT-5-nano 在长程任务上掉链子。Qwen3.5 推理最快。无限任务下，模型难以判断环境是否探索完毕，导致失败。图 3 显示推理时间差异。环境 B 比环境 A 更难，新物体触发重规划。结果显示，虽然代码生成可靠，但语义 grounding 仍是瓶颈，尤其在多步推理和计数任务上。
