Tycho: Active Abstraction with Programmatic World Models for ARC-AGI-3

Jens Lehmann, Andrei Aioanei, Sahar Vahdati
abspdf

论文点评Review

这篇论文给 ARC-AGI-3 的“抽象”概念上了个紧箍咒。作者把游戏形式化为渲染的 Moore 机，听起来很硬核，其实就是让 Agent 写 Python 脚本模拟游戏逻辑。最讽刺的是，自动修复模型虽然让模拟更准了，但玩分反而低了，说明“算得对”不等于“玩得溜”。Tycho 的核心贡献其实是“元认知”：别瞎建模型，得看值不值。不过，依赖 Python 解释器作为世界模型，在复杂物理交互上可能有点悬，毕竟 ARC 是网格游戏，不是机器人控制。总之，这是一篇把“写代码”包装成“主动抽象”的佳作，但别指望它能直接迁移到真实机器人，毕竟真实世界没有现成的 init_state 函数。
—

研究动机Motivation

智能的核心不是存储方案，而是从少量经验中获取技能（Chollet, 2019）。ARC-AGI-3 将这一挑战推向交互式场景，每一步动作都计分，Agent 必须在探索世界机制和节省动作预算之间权衡。现有工作如 DreamTeam (Sarafian et al., 2026) 或 OPINE-World (Courtis et al., 2026) 虽然引入了可执行模型，但往往默认模型构建是必须的，或者仅关注模型本身的合成质量，忽略了“何时构建”和“谁来构建”的元认知决策。Kamradt (2026a) 指出前沿模型常出现局部正确但全局模型错误的情况。Tycho 旨在解决“主动抽象”问题：如何从昂贵交互中生成可测试模型，并判断获取或使用该模型是否值得其成本。这不仅是模型构建，更是资源分配问题。
—

方法Method

Tycho 的整体架构围绕“证据 - 假设 - 行动”循环展开。首先，环境被形式化为参数化渲染确定性 Moore 机，包含潜在状态、动作转换、渲染网格及过渡帧（Figure 2）。Agent 维护一个结构化交互历史，区分决策帧、动画帧和终止帧。核心是“可执行假设语言”，即一个 Python 程序，包含 init_state、transition、render 和 outcome 四个函数，允许 Agent 自由定义状态表示（如计数器、对象列表）。验证模块通过重放历史轨迹检查模型预测与观测的一致性，支持部分输出预测（Figure 3）。规划模块从模型重放后的状态出发搜索目标状态。最关键的是元推理策略（Figure 1），比较四种策略：无模型、Actor 自建、Orchestrator（委托构建者）、Trigger（自动修复）。数据流上，Actor 负责决策，可选工作bench负责模型构建与验证，确保动作提交权始终在 Actor 手中。
—

实验Experiments

在 25 个公开 ARC-AGI-3 游戏（183 个关卡）上评估了四种编排策略。使用 Claude Opus 4.8 进行匹配推理预算比较。结果显示，Actor 请求委托（Orchestrator）策略获得最高平均 RHAE（88.49）。使用 GPT-5.6 Sol 和 Opus 5 评估选定策略时，两者均达到 100.00 RHAE，Opus 5 比人类基线少用 61% 动作。消融发现，自动修复（Trigger）虽然提高了模型过渡匹配准确率，但 RHAE 降至 83.07，证明模型准确性不等于游戏表现（Figure 8, Figure 9）。这验证了主动抽象中“决策何时使用模型”比“模型有多准”更重要。
