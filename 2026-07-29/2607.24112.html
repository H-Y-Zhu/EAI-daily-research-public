Scaling GUI Agents with Visual State Transitions

Xiangyan Liu, Kaixin Li, Haonan Wang, Biao Wu, Meng Fang, Longxu Dou
abspdf

论文点评Review

这篇论文给 GUI Agent 的 Scaling Law 加了个新维度，叫 STP。说白了就是别光盯着任务指令微调，先把“状态变化”学明白。Forward 和 Inverse Dynamics 双管齐下，确实比单练强。但吐槽一下，这“新数据”大部分还是从现有轨迹里拆出来的，算不算“换汤不换药”？不过能证明纯视觉动态建模对 Agent 有用，还是值得点赞。基线对比做得挺扎实，但移动端提升小，可能因为任务太简单或者模型早见过。总之，是个实用的工程优化，别指望它直接解决长程规划难题，但在数据效率上确实有贡献，适合资源受限场景，值得跟进。
—

研究动机Motivation

GUI Agent 训练主要靠 RL 或轨迹微调。RL 需要复杂环境，工程量大 (Ye et al., 2025; Lu et al., 2025b)。轨迹微调虽主流，但多步轨迹标注贵 (Lu et al., 2025c; Wang et al., 2025c)。且直接微调把视觉定位、动态建模、任务规划全耦合在一个目标里，优化难、数据效率低 (Cheng et al., 2024)。现有方法缺乏对 GUI 动态的显式建模。STP 旨在解耦这些能力，利用廉价的步级状态转换数据，提供更好初始化，作为轨迹微调的补充 Scaling 轴，降低对高质量指令数据的依赖，解决数据稀缺和耦合优化难题。
—

方法Method

整体流程分两阶段：先 STP 预训练，再轨迹微调。数据源是现有轨迹拆解的 (st, at, st+1) 元组，无需任务指令。核心创新是双目标联合优化：1) Inverse Dynamics：输入前后截图，预测动作 (at)，强迫模型关注交互区域和视觉变化，提取细粒度特征。2) Forward Dynamics：输入当前状态和动作，预测下一状态 (st+1)，让模型内化 GUI 动态世界模型。两者在统一多模态模型 (UMM, 如 BAGEL) 上联合训练。预训练后，冻结或微调模型进行下游任务微调。相比仅微调，STP 提供了更优的初始化，且 Forward 目标比单纯图像重建更能捕捉动作效应，需更新整个模型而非仅视觉编码器，确保语言组件也能理解视觉动态。
—

实验Experiments

在桌面 (AgentNet) 和移动 (AndroidControl, GUIOdyssey) 场景测试。基线是仅轨迹微调 (FT w/o STP)。指标包括成功率 (SR)、坐标定位 (Grounding)。结果显示 STP 在所有设置下均提升性能，桌面提升更明显 (AgentNetBench 平均 SR 提升 2.3%-6.2%)。移动端提升较小，归因于任务简单或模型预训练已覆盖。消融实验证明联合优化优于单目标，且增加转换数据量能持续提升性能。采样粒度（轨迹级 vs 步级）影响不大。此外，STP 还能缓解域偏移问题，在 Win&Mac 预训练后微调 Ubuntu 轨迹时提升显著。
