Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

Ruiyang Si, Jianxin Bi, Shunyu Yang, Rui Ni, Wenbo Huang, Qiang Wang
abspdf

论文点评Review

这篇论文本质上是在给大模型机器人“减肥”。PyRUA-Lean 通过把 VLM 从“每步都问”变成“写代码批量处理”，成功把 token 消耗砍了 65%，成功率还涨了 14%。这招“代码即策略”在机器人领域不算新鲜，但作者聪明地结合了 RPent 的底层能力，用 Python 的持久化状态和条件判断替代了反复的 LLM 调用。不过，别高兴太早，这主要是仿真环境下的胜利。在物理机器人上，代码执行延迟、异常处理会不会反噬效率？而且 GPT-6 Astra 这种闭源模型的表现，能不能迁移到其他开源基座？论文虽然数据漂亮，但把“接口设计”和“模型能力”混在一起评测，到底是谁在起作用，还得打个问号。总的来说，是工程优化的胜利，而非算法的突破，适合对推理成本敏感的场景。

研究动机Motivation

现有的 VLM 机器人控制大多依赖 tool-calling 接口，每次动作执行后都需要 VLM 重新观察并决策，导致中间结果累积在对话历史中，token 开销巨大 [33]。即使单个原语可靠，重复定位、运动和恢复也会带来大量推理开销。虽然 Code as Policies 等早期工作尝试用代码生成程序 [14, 25]，但缺乏对执行反馈的细粒度控制。通用 Agent 研究已证明可执行代码能减少上下文信息 [2, 29]，但在具身控制中，视觉观测和原语失败的处理更复杂。本文旨在解决 VLM 代理如何通过程序化组合原语来减少 token 消耗，同时保持任务完成率。核心问题是：如何在减少 LLM 调用的同时，利用代码逻辑处理中间状态和选择性观察？
—

方法Method

PyRUA-Lean 是一个基于 Python 的交互式代码执行框架，构建在 RPent 机器人栈之上。整体流程是：VLM 生成包含机器人原语调用的 Python 代码单元格（cell），运行时执行代码，仅将显式请求的反馈（如特定图像或状态）返回给 VLM 用于下一轮规划。创新点包括：1. 反馈驱动的原语组合：代码单元格内可连续调用多个原语（如移动、抓取），并根据执行结果（如是否成功）进行条件分支或本地重试，无需额外 LLM 调用。2. 选择性观察与上下文管理：中间结果保存在持久化命名空间中，不全部进入 LLM 上下文，仅通过 robo.show 等显式请求返回图像，大幅减少输入 token。3. 几何计算与辅助函数：允许在代码中直接进行几何计算（如平面拟合）或定义辅助函数，增强规划能力。相比工具调用，这种模式将中间协调和计算移至运行时，减少了 VLM 的交互频率。
—

实验Experiments

在 LIBERO-PRO、RoboTwin 2.0 和 RoboCasa365 的 700 个仿真任务实例上评估。基线为使用相同 GPT-6 Astra 和 RPent 原语的 tool-calling 代理。指标包括成功率、LLM 调用次数、输入 token 数和成本。结果显示，PyRUA-Lean 整体成功率从 63.1% 提升至 71.7%，在共同解决的实例上 LLM 调用减少 49%，token 减少 65%。消融实验表明，即使移除 VLA 策略或操作指南，代码代理仍保持更高效率和成功率。失败案例分析显示，代码代理在几何推理和脚本恢复上表现更好，但 VLA 主导的任务中效率增益较小。此外，在 RoboDojo 上的试点也验证了 token 效率。
