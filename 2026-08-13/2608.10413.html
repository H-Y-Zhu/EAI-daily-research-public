DriveVLA-M0: Failure-Aware Memory Augmentation for Autonomous Driving

Zebin Xing, Yupeng Zheng, Qiang Chen, Linbo Wang, Yichen Zhang, Pengxuan Yang
abspdf

论文点评Review

DriveVLA-M0 这论文算是给 VLA 自动驾驶开了个“后悔药”小灶。它没搞花哨的 RL 微调，而是搞了个“失败记忆库”，专门记仇。核心逻辑是：既然模型容易在特定场景翻车，那就把翻车现场存下来，推理时搜一搜相似路况，用 LoRA 现场改改参数。这招确实灵，NAVSIM 上刷了个 SOTA，PDMS 干到 94.1。不过，TTT 带来的推理延迟虽然只有 26ms，但在实时性要求极高的车端，这 26ms 是不是有点“肉疼”？另外，依赖 Oracle 评分来筛选失败样本，这门槛是不是有点高？毕竟真路上哪有那么多完美标签。总的来说，是个聪明的工程 trick，把“事后诸葛亮”变成了“事前预警”，但泛化能力还得看内存池扩得有多大，毕竟内存大了检索成本也上去了。
—

研究动机Motivation

现有的 VLA 模型在自动驾驶里有个通病：记吃不记打。遇到类似场景容易重复犯错，缺乏从历史失败中学习的机制。虽然有些工作引入了记忆模块，比如 MemoryVLA [36] 和 MTRDrive [29]，但它们大多依赖 Vision-Language 特征作为检索键。问题在于，自动驾驶决策更依赖道路拓扑和动态交互结构，光靠语义特征检索，容易找到“看起来像但结构不对”的样本，导致修正无效。人类驾驶时会关联历史错误来调整行为，但机器还没学会这招。因此，如何构建一个能理解“结构相似性”而非“语义相似性”的失败记忆系统，并实现高效的在线修正，就成了关键痛点。现有方法忽略了静态道路和动态智能体的解耦，导致检索精度不足。
—

方法Method

整体流程分离线和在线两阶段。离线阶段构建“失败记忆池”：用基座模型跑数据，通过 Oracle 评分（PDM）筛选低分场景，提取地图（Map）和智能体（Agent）的结构特征存入 Latent Memory。在线阶段是“推理即训练”：遇到新场景，用专用的 Retrieve Model 提取结构特征，在内存里搜相似失败案例。这里用了 DINOv2 加 LoRA 的轻量架构，解耦 Map 和 Agent 分支。如果相似度够高（Trigger 机制），就激活 Decoupled LoRA 进行 Test-Time Training。这里有个亮点是解耦设计：地图特征微调静态 LoRA 分支，智能体特征微调动态 LoRA 分支，分别修正道路合规和避障能力。最后融合两路分数选轨迹。这种设计避免了全量微调的开销，只改关键参数，实现了场景特定的快速适应，且无需修改 Backbone。
—

实验Experiments

在 NAVSIMv1 和 NAVSIMv2 两个基准上测试。Navtest 上 PDMS 达 94.1，Navhard 上 EPDMS 47.0，均优于现有 SOTA。对比基线包括 TransFuser、Centaur 等。消融实验显示，仅用语言特征检索效果不如结构特征，Map+Agent 组合最好。Trigger 阈值设为 0.9 时平衡了修正覆盖率和噪声风险。延迟测试显示 TTT 反向传播仅增加 26.44ms，可接受。此外，内存池扩大无需重训即可提升性能，证明了可扩展性。可视化显示 TTT 后轨迹分布向 GT 偏移，修正有效。具体指标如 NC、DAC 也有显著提升，说明安全性增强。
